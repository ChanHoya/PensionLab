# Failure Patterns

- **FP-001**: Prisma 7 does not support `url` in `schema.prisma`. Always configure connection urls in `prisma.config.ts` and instantiate the client using `@prisma/adapter-pg`.
- **FP-002**: Local `pgvector` compilation must match the target PostgreSQL instance version (e.g., PostgreSQL 16 instead of 17/18 installed by default on brew).
- **FP-003**: In Next.js client components utilizing SSR with dynamic libraries (like Recharts), always wrap the component rendering in client-side mounting protection (e.g., `isMounted` state checked after `useEffect` mount) to prevent React hydration mismatch warnings.
- **FP-004**: Executing batch scripts via standard `node` that require TypeScript imports (such as custom-generated Prisma Clients) will fail in CJS. Always execute them using `tsx` (e.g., `npx tsx scripts/script-name.ts` or configure script scripts using tsx).
- **FP-005**: In Next.js App Router, client-side components that call `useSearchParams()` must be wrapped in a `<Suspense>` boundary. If they are not wrapped, Next.js bails out of static generation, causing `next build` to fail during prerendering.
- **FP-006**: In Next.js App Router (Turbopack), changes to `.env` variables (e.g., Codef API credentials) might not automatically clear cache for dynamic route handlers. The dev server must be manually restarted to reload environment variables.
- **FP-007**: When testing PASS Easy Authentication via Codef, the telecom carrier code (`telecom`: SKT "0", KT "1", LGU+ "2") is a mandatory parameter. Missing carrier codes will prevent the authorization push from reaching the smartphone.
- **FP-008**: FSS API(통합연금포털) 연동 시, 다수의 계좌 정보가 단일 API 응답으로 함께 반환됩니다. 이를 Zustand 스토어에 바인딩할 때 기존 저장된 계좌들을 먼저 클리어하지 않으면 이전 수동 입력값이나 기존 정보와 합산되어 중복 누적 연산 에러가 발생하므로, 일괄 삭제 후 추가 루프를 돌아야 합니다.
- **FP-009**: 서버리스 호스팅(Vercel) 환경에서는 다중 콜드 스타트로 인해 DB 커넥션 풀이 쉽게 한도에 도달하여 Prisma `$transaction`이 시작 시간 내에 커넥션을 획득하지 못해 타임아웃 오류가 발생합니다. `pg.Pool`에 `max` 한도를 조이고 `idleTimeoutMillis`를 짧게 주어 즉각 반환되도록 방지해야 합니다.
- **FP-010**: Recharts' `ResponsiveContainer` inside CSS Flexbox layouts with `height="100%"` will fail to determine its target rendering height, collapsing to 0px. Always define a explicit static `height` on the parent wrapper div or set the height parameter directly inside the Recharts container.
- **FP-011**: Next.js App Router 브라우저 환경에서 `pdfjs-dist`를 사용하여 PDF 텍스트를 파싱할 때, webpack worker 로딩 오류를 방지하기 위해 라이브러리를 Dynamic Import(`await import("pdfjs-dist")`)로 처리하고, `pdfjs.GlobalWorkerOptions.workerSrc` 경로를 패키지의 내부 버전을 활용해 신뢰할 수 있는 CDN 주소(예: `https://cdn.jsdelivr.net/npm/pdfjs-dist@${pdfjs.version}/build/pdf.worker.min.mjs`)로 동적 바인딩해야 정상 동작합니다.
- **FP-012**: React/JSX 코드 작성 시 동일 요소에 여러 개의 `style` 속성을 중복 선언하면 `TS17001: JSX elements cannot have multiple attributes with the same name.` 컴파일 에러가 발생합니다. 여러 스타일을 동적으로 입힐 때는 객체 스프레드 연산자(`style={{ ...styleA, ...styleB }}`)를 사용해 하나로 합산하여 적용해야 합니다.
- **FP-013**: Recharts `Tooltip` 컴포넌트의 `formatter`에서 첫 번째 매개변수(`value`)는 TypeScript 컴파일러에 의해 `undefined` 가능성이 있는 것으로 판별될 수 있습니다. `value`에 대해 안전한 nullish 체크(예: `value ? ... : ""`)를 선행 처리하지 않으면 `TS18048: 'value' is possibly 'undefined'.` 오류가 발생합니다.
- **FP-014**: 은퇴 인출 시뮬레이션 알고리즘에서 계좌 잔액(`acc.balance`)만 복리 이자가 붙고 세부 세제원(`acc.sources`)에 복리 이자가 가산되지 않으면 기말로 갈수록 재원 매칭 불일치가 누적됩니다. 이는 최종 연차에 세금 계산 누락으로 인한 비정상적인 수령액 피크(Peak)를 유발합니다. 또한 단순 `잔액 / 남은기간` 분할 방식은 복리 효과가 누적될수록 기말 인출액이 치솟는 문제를 만듭니다. 이를 방지하기 위해 계좌 잔액과 세제원을 동일한 연치 이자로 복리 동기화하고, 인출금액은 최초 1회 Annuity PMT 공식을 이용해 기준 인출액을 고정해 두고 평탄화 인출을 해야 기말 피크 없이 자산이 0으로 정확히 소멸합니다.
- **FP-015**: 인출 시뮬레이션 구축 시 수령 개시 연도까지 이미 미래가치(FV)로 계산된 기초 평가액에 대해, 시뮬레이션 루프의 시작 나이(`currentAge`)부터 수령 나이(`payoutStartAge`) 사이의 대기 기간 동안 이자가 한 번 더 복리로 부과되는 **더블 복리(Double Compounding) 오류**를 경계해야 합니다. 이를 방지하기 위해 이자 가산 및 세제원 복리 동기화 조건에 반드시 수령 개시 여부(`age >= acc.payoutStartAge`)를 추가해야 하며, 수령 대기 중인 자산의 경우 미래가치를 남은 대기 기간만큼 역산 할인(Discounting)하여 화면에 점진적으로 우상향 성장하는 정상 추이를 보여주어야 합니다.
- **FP-016**: 인출 시뮬레이션 시 시작 시점에 자산의 미래가치(FV)를 미리 계산해 두고 시뮬레이션 루프에서 할인(Discount)하는 설계는 인출 시작 시점이 동적으로 변경될 때(예: 평탄화 전략 적용에 따른 개인연금 개시 연기 등) 복리 이자가 누락되거나 이중 복리가 발생하는 등 정합성 오류를 만들기 쉽습니다. 이를 방지하기 위해 시뮬레이션 시작 시점에는 계좌 평가액을 **현재 나이 시점 금액**으로 초기화하고, 시뮬레이션 연도별 루프 안에서 매년 말 기여금 추가 및 복리 연산을 동적으로 순차 진행해야 인출 시점 변경 및 조기/연기 시나리오를 가장 수학적/논리적으로 정밀하게 시뮬레이션할 수 있습니다.
- **FP-017**: 건보료 피부양자 자격 방어 및 지역보험료 산출 시, 금융소득(이자 및 배당소득)은 연 1,000만원 허들 룰이 적용됩니다. 1,000만원 이하면 합산소득에 합산되지 않지만(0원 처리), 1,000만원을 초과하면 금융소득 **전액**이 합산소득에 산입되며 지역건보료 부과 시에도 초과분이 아닌 전체 금융소득에 대해 보험료(7.09%)가 부과됩니다. 또한 부부 명의 분산 시에는 1인당 한도(1,000만원)가 독립적으로 적용되지만, 둘 다 탈락 시 지역보험료가 각각 청구되어 총 보험료가 2배가 되는 정합성 로직을 계산 엔진과 UI에 누락 없이 반영해야 합니다.
- **FP-018**: 고해상도 와이드 화면(`maxWidth: 1680px` 등)을 브라우저 뷰 그대로 `html2canvas`로 캡처하여 A4 세로 규격(210mm)으로 출력하면, 캔버스 가로폭이 커서 PDF 상의 폰트 및 차트 요소가 과도하게 축소되어 가독성이 현저히 떨어집니다. 이를 해결하기 위해 화면 표시용 와이드 컨테이너와, A4 인쇄 가독성에 최적화된 독립 규격(`width: 1040px`, `position: fixed; left: -9999px`)의 오프스크린 인쇄 전용 렌더링 컨테이너(`<DiagnosisReport isPrintMode={true} />`)를 분리하여 PDF 다운로드 시 해당 오프스크린 엘리먼트를 캡처하도록 구현해야 화면의 와이드한 사용자 경험과 PDF 출력물의 선명한 가독성을 동시에 만족할 수 있습니다.
- **FP-019**: 연차별 지출 곡선(Spending Curve) 모델링 시 연금 인출 함수의 인덱스/인수 불일치 및 단조성 보장 오류를 경계해야 합니다. 연차별 인출 함수(예: `drawAt(L, g, t)`)의 시그니처가 지출 곡선 도입으로 변경되거나 경과 연수(`t - start`)를 상대 가중치(`weightAt`)로 환산할 때, 절대 연도 인덱스와 은퇴 후 경과 연수(`relT`)의 구분이 모호하면 음수 인덱스 접근이나 만료 후에도 인출이 종료되지 않는 엣지 케이스가 발생합니다. 또한 시작 인출 수준 $L$을 이진 탐색할 때 곡선의 가중치 경로가 비단조적이거나 바닥선 제한(`minFloor`)이 불연속적이면 수렴 실패가 발생할 수 있으므로, 목적 함수 `need(L)`가 $L$에 대해 엄격히 단조 증가함을 보장하고 `relT < 0` 또는 `t > end`인 구간에 대해 명확한 zero-guard를 두어야 합니다.
- **FP-020**: 대시보드 시뮬레이션과 AI 진단 리포트 간 화폐가치 기준(명목 vs 실질 구매력)이 상이하거나 불일치할 경우, 물가상승률(연 3%)이 누적된 국민연금 명목 수령액이 현재가치 기준의 생활비선(월 300~450만원 등)을 과도하게 초과하는 왜곡이 발생하여 연금 충분성을 과대평가하게 됩니다. 이를 방지하기 위해 서비스 전반의 기본 화폐가치를 **'현재가치(실질 구매력)'**로 일원화하고, `CoupleSimulationSection` 및 현금흐름 차트에 `[현재가치(실질) | 명목 금액]` 토글 스위치를 제공하여 명확한 선택권을 부여해야 합니다. 실질 모드에서는 국민연금의 물가 연동액을 할인하여 평평한 구매력 보존 수평선으로 나타내고, 생활비선과 동일선상에서 정밀 비교할 수 있도록 정합성을 확립해야 합니다.
- **FP-021**: 연령대별(60대, 70대, 80대, 90대+) 계단식 생활비 설계 시 연령대 경계(69→70세, 79→80세 등)에서 급격한 절벽형(Cliff) 단절이 발생하면 시각적 위화감과 평탄화 인출 알고리즘 왜곡을 유발합니다. 또한 지출 곡선의 최대 연령(Horizon)이 90세 등으로 고정되어 있으면 부부 최장 수명(100~105세) 시뮬레이션 시 90세 이후 데이터 결측으로 인해 default fallback(월 600만원 등)이 발동되어 붉은 지출선이 기말에 치솟는 버그가 발생합니다. 이를 방지하기 위해 전환 연령 구간에 1년 선형 보간(Linear Interpolation) 스무딩을 적용하고, 지출 곡선 생성 시 `maxAge`를 부부 최장 수명에 넉넉한 버퍼를 더한 최소 105세까지 안전하게 산출하며, 마지막 유효 연령 값을 안전하게 복제(clamp fallback)하도록 방어 코드를 구축해야 합니다.
- **FP-022**: 대시보드 시뮬레이션 및 진단 리포트에서 긴 설명글(법적 근거, 연복리 산정 원리, 유족연금 계산표 등)을 세로로 나열하면 화면 스크롤 길이가 과도하게 늘어나고 주요 시각 지표(KPI, 차트)의 가시성이 저하됩니다. 또한 다수의 `<details>`를 단순 수직 배치하면 스크롤 피로감을 유발합니다. 이를 해결하기 위해 긴 설명 요소는 가로 4열의 키워드 탭 바(`criteriaBar`)로 배치하고, 클릭 시 선택된 탭만 하단으로 부드럽게 펼쳐지는 단일 드롭다운(`activeCriteriaTab`) 구조로 압축해야 합니다. 줄어든 상단 여백에는 핵심 결과 지표(은퇴 후 평균 월 연금, 생애 총 수령액 등)를 카드 형태로 배치하고, 통화 기준(실질 구매력 vs 명목) 토글과 실시간 연동되도록 설계하여 정보 접근성과 시각적 컴팩트함을 동시에 극대화해야 합니다.
- **FP-023**: React 컴포넌트 내 조건부 조기 반환(`if (!isMounted) return ...` 또는 `if (loading) return ...`) 뒤에 React Hook(`useState`, `useMemo`, `useEffect` 등)을 선언하면, 초기 렌더링과 마운트 완료 후 재렌더링 시 호출되는 Hook의 개수와 순서가 달라져 `Rendered more hooks than during the previous render.` 런타임 에러(React Rules of Hooks 위반)가 발생합니다. 모든 React Hook은 반드시 컴포넌트 최상단, 즉 **어떠한 조건부 조기 반환문보다도 앞서서 무조건 호출**되도록 선언해야 하며, 조기 반환문 이후에 필요한 파생 데이터 가공은 Hook이 아닌 순수 연산(IIFE 또는 함수 계산)으로 처리해야 합니다.
- **FP-025**: 사적연금(연금저축/IRP) 1,500만원 절세 한도 산정 시 문턱 효과(Cliff Effect) 주의: 세액공제분 및 운용수익 수령액이 연 1,500만원을 단 1원이라도 초과하면 초과분이 아닌 당해 연도 사적연금 수령액 **전체**에 대해 저율 분리과세(3.3~5.5%)가 배제되고 16.5% 기타소득 분리과세 또는 타 소득과의 종합과세가 강제됩니다. 따라서 10년 등 단기 집중 수령 대신 15~20년으로 수령 기간을 늘려 연간 수령액을 1,500만원 이하로 억제하는 '분산 평탄화(Spread & Leveling)' 최적화 알고리즘 및 시각화 가이드가 필수적입니다.
- **FP-026**: 주택연금(역모기지)의 비과세 대출금 특성 및 HF 제도 정합성: 주택연금은 법적으로 '주택담보대출 분할금'이므로 연금소득세 및 지역건강보험료 산정 시 소득 합산액이 0원(완전 비과세)입니다. 또한 공시가격 12억원 상한 초과 주택의 경우 12억원 기준 월지급금으로 제한되며, 종신지급형은 연령별 월지급금 계수를 선형 보간하여 정밀 산출해야 합니다. 사후 정산 시 비소구 대출(부족분 미청구, 잉여분 상속) 원칙을 안내 및 계산 모델에 일관되게 반영해야 합니다.
- **FP-027**: 국민연금법 제56조 유족연금 중복급여 조정 및 가입기간별 차등 지급률: 수급권자에게 본인 노령연금과 배우자 사망에 따른 유족연금이 동시 발생할 경우, 병급 제한 원칙에 따라 [대안 A: 본인 노령연금 + 유족연금액의 30%]와 [대안 B: 본인 노령연금 포기 + 유족연금 100%] 중 유리한 금액(`Math.max(A, B)`)을 선택해야 합니다. 또한 유족연금 원액 산정 시 사망자의 국민연금 가입기간(20년 이상 60%, 10~20년 미만 50%, 10년 미만 40%)에 따른 기본연금액 지급률을 정밀 반영해야 시뮬레이션 금액 왜곡을 방지할 수 있습니다.
